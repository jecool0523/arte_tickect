# ARTE 티켓팅 작업 정리 — 2026-10-06

## 사용자 화면

하단 내비게이션은 **홈 / 공연 / 아르떼 / 프로필**이다. 프로필에서 내 정보, 이메일 인증 상태, 공연별 내 티켓, Google 사진 동기화, 로그아웃 및 계정 탈퇴를 관리한다.

첫 로그인 또는 미등록 계정은 `/profile/setup`에서 아이디·이름·학번·연락처를 필수 입력한다. 아이디 기본값은 이메일의 `@` 앞부분이며, 허용 형식에 맞게 영문·숫자 외 기호를 제외한다. 사용자가 수정할 수 있고 대소문자를 구분하지 않는 중복 검사가 적용된다. 로그인 방식은 Google OAuth를 유지하며 학교 이메일 도메인 제한은 없다.

## 이전 예약 연결

- 입력한 이름·학번을 양끝 공백 제거 후 모두 정확히 대조한다. 이메일/Google 이름으로 신원을 확인하지 않는다.
- 현재 공연 3개 테이블과 레거시 `arte_musical_tickets`에서 미연결 예약만 가져온다. 다른 계정의 예약은 재배정하지 않는다.
- 정보 저장, 로그인 callback, 프로필 조회 시 연결을 확인하고 반복 연결은 중복되지 않는다.
- 연결된 예약이 있는 완료 프로필의 이름·학번은 변경을 제한한다. 아이디·연락처는 변경할 수 있고, 기존 예매 계정의 최초 등록도 허용한다.
- 연락처와 티켓은 본인 전용 RLS로 조회한다. 실제 예약의 일괄 백필은 수행하지 않았다.

이름·학번 입력을 신뢰하는 방식이므로 두 값을 아는 다른 사람이 먼저 등록하면 잘못 연결될 수 있다. 소유 계정 보호와 중복 방지가 본인 인증을 대체하지는 않는다. 상세 규칙과 원격 마이그레이션 이름은 [프로필 문서](profile-onboarding.md)에 있다. 원격 Supabase history를 기준으로 하며 예전 레거시 SQL을 일괄 실행하지 않는다.

## 기존 UI 스타일 통일

홈·공연·아르떼 화면의 기존 패턴을 기준으로 로그인·프로필·정보 등록 화면을 맞췄다. 새 패키지를 설치하거나 전역 테마/기존 UI primitive를 변경하지 않았다.

| 요소 | 적용 규칙 |
| --- | --- |
| 화면 프레임 | `AccountPageShell`: `h-[100dvh]` flex, 회색 배경, 흰색 헤더, 가운데 18px 제목 |
| 본문 | 최대 `max-w-2xl`, 16px 바깥 여백, 본문 독립 스크롤 |
| 카드 | 기존 `Card`: `rounded-lg`, `border-gray-200`, 흰색, `shadow-sm` |
| 주 동작 | 기존 `Button`: `bg-purple-600`, hover `purple-700`, 높이 44px |
| 보조 동작 | 흰색 outline 버튼, 회색 테두리와 텍스트 |
| 입력 | 기존 `Input`/`Label`, 회색 테두리, 보라색 focus, 읽기 전용 회색 배경 |
| 하단 내비게이션 | 기존 `AppBottomNav`, 흰색 배경, 회색 경계선, safe-area 반영 |

프로필의 어두운 대형 히어로/그라데이션과 로그인 페이지의 별도 그라데이션을 제거했다. 로그인과 정보 등록에도 동일한 헤더·탭바를 사용한다. footer가 본문을 가리지 않도록 flex 영역을 분리하고 긴 이메일·좌석 목록은 줄바꿈한다. 취소된 티켓은 회색 상태 배지로 구분한다.

입력 label, 필수 입력, validation 상태 알림, pending 시 비활성화, 수정 금지 상태 및 탈퇴 확인 단계는 유지했다. 헤더 홈 버튼에 접근 가능한 이름이 있고, 탭바의 현재 페이지 표시도 유지한다.

## 배포와 보호 설정

- Next.js / OpenNext / Wrangler 기반 Sites Worker 빌드와 공식 소스 저장·포장 흐름을 구성했다. 기존 GitHub `origin`과 Sites 접근 범위를 유지한다.
- 개발 미리보기는 `.next-dev`, 배포 빌드는 `.next`로 분리했다. 미리보기를 켜 둔 상태에서 배포 빌드를 해도 개발용 manifest/runtime이 포장에 섞이지 않게 한다. 두 생성 디렉터리는 Git에서 제외한다.
- 실제 Sites 주소와 OAuth 기준 URL을 일치시키고 환경 변수 누락/불일치 시 fail-closed로 처리한다. 서버 비밀값은 런타임 변수로 주입하며 소스·정적 파일·배포 번들에 굽지 않는다.
- 개인 경로/세션 응답은 private/no-store이다. 미로그인 프로필·예매 화면은 로그인으로 이동하고, 수정·예매 API는 401, 미등록 계정의 예매는 403이다.
- 관리자 목록은 먼저 사용자/관리자 권한을 검사한다. 누락된 권한 RPC는 접근 허용으로 처리하지 않는다. 임의의 관리자/사전 예매 권한을 부여하지 않았다.
- 원격 프로필 및 후기 RPC의 앱 호환성을 보완했다. 기존 리뷰 비밀번호 데이터는 보존하고 현재 앱의 삭제 토큰 방식을 지원했다.

상세 실행 환경, 비밀 변수 관리 및 Windows 빌드 호환은 [배포 문서](sites-deployment.md)를 참고한다.

## 검증 및 한계

입력 기본값/필수 필드/연락처 정규화, 프로필 폼 렌더링, API의 검증된 UID 사용/중복 응답/요청 제한, 설정 오류 시 차단, Worker 경로·정적 JS·개인 캐시·콜백 경로 및 비밀값 미포함을 검사한다. 변경 후 전체 배포 빌드와 로컬 Worker 검사를 다시 실행한다.

이번 UI 변경은 로컬 브라우저에서 데스크톱 및 390px 모바일 화면으로 정보 등록 화면을 확인했다. 가로 넘침 없이 본문이 스크롤되며 저장·로그아웃 버튼은 하단 탭바 위에서 접근 가능하다. 실제 이용자의 정보를 저장하거나 예약을 연결하는 조작은 하지 않았다. 로그인 화면은 비로그인 HTTP 렌더링으로 200 응답과 공통 프레임·내비게이션을 확인했다.

이전 DB 테스트는 임시 사용자/예약만 만든 트랜잭션을 ROLLBACK하여 실제 예약을 보존했다. 정확한 이름+학번 대조, 기존 소유 보호, 반복 동기화, 중복 아이디, 최초 등록, 연결 후 신원 변경 제한, RLS 및 탈퇴 정리를 통과했다. 실제 Supabase REST에서 서버 RPC 사용 가능/익명 호출 차단도 확인했다.

실제 Google 계정으로 로그인 완료부터 저장까지의 최종 확인은 아직 별도 사용자 확인이 필요하다. Supabase Auth Redirect URLs에는 `https://dimi-arte-ticket.gpt-class2-4.chatgpt.site/auth/callback`이 있어야 한다. Supabase advisors의 기존 GraphQL 노출 및 유출 비밀번호 보호 비활성화 경고는 남아 있으며, 이 작업이 전체 보안 인증을 의미하지 않는다.
